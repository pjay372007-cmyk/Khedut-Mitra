# KrishiAI Task Template (KES v1.0)

All development tasks, sprint features, and bug fixes proposed to engineers or AI coding assistants must adhere to the following template structure.

---

```markdown
# TASK_ID: [PROJECT]-[SPRINT]-[COMPONENT_NAME]

## ROLE:
Describe the engineering role expected for the task (e.g. Senior Machine Learning Engineer, Full-Stack Engineer, Frontend Architect).

## OBJECTIVE:
Define the primary goal of the task, the problem it solves, and the context of the change.

## CONSTRAINTS & DO NOTs:
List explicit boundaries (e.g., do not hardcode, do not rewrite files, do not break existing CSS/styling).

## FUNCTIONAL REQUIREMENTS:
1. [Requirement 1]
2. [Requirement 2]
3. [Requirement 3]

## NON-FUNCTIONAL REQUIREMENTS:
- Standard quality goals (SOLID principles, Type hints, Docstrings, Logging, config-driven, etc.).
- Performance, security, or testing guidelines.

## EXPECTED DELIVERABLES:
1. Files Created (list exact file paths and names)
2. Files Modified (list exact file paths and names)
3. Architecture Notes (explain design decisions)
4. Key Risks & Mitigation
5. Future Improvements

## SUCCESS CRITERIA:
✓ All unit tests pass successfully.
✓ Enforces KrishiAI Engineering Standard v1.0.
✓ Verified on local browser page (e.g., http://localhost:8000).
```
